Title: chore: repository skeleton, Python tooling and CI gate
Labels: priority: P0

## Why
Every later mission needs a place to put code, a `check` command and a CI gate that blocks merges. Without them, quality depends on remembering to run things.

## Scope
- Folders `core/`, `packs/`, `evals/`, `tests/` with a minimal package that imports (`workflows/` only gets a README saying it arrives with n8n).
- Python environment: pick the tool (recommendation in `docs/ARCHITECTURE.md` D7: uv + ruff + pyright strict + pytest + poethepoet), confirm against the official docs, record the decision and source in D7. Pin the Python version.
- `check` task (lint, format check, types) and `test` task; confirm the contract table in `AGENTS.md`.
- `pydantic-settings` config loaded and validated at startup; `.env.example`; `.env` in `.gitignore`.
- GitHub Actions: jobs `check` and `test`, actions pinned by full commit SHA with `# vX.Y.Z`, `permissions: contents: read`, `persist-credentials: false`, `timeout-minutes`, `concurrency`; aggregator `ci-passed` using `always()` that fails if any needed job did not succeed.
- Security jobs reused from the other repos: `secret-scan` (gitleaks), `workflow-audit` (zizmor), dependency audit.
- `dependabot.yml` (grouped minor/patch, 7-day cooldown) for the package manager and GitHub Actions.
- Repository settings (confirm with the user first): squash merge with PR title and body, auto-merge allowed, ruleset on `main` requiring `ci-passed`, up-to-date branch and linear history; labels `priority: P0/P1/P2`.

## Acceptance criteria
- [ ] `check` and `test` pass locally and in CI.
- [ ] RED proven for each gate with a probe: a lint error, a type error, a failing test, a fake secret (throwaway PR) and a job left out of `ci-passed`'s `needs` each make CI fail for the right reason.
- [ ] Ruleset active; a PR cannot merge without `ci-passed`.
- [ ] D7 updated with the chosen tools and sources.

## Out of scope
Any pipeline logic. n8n.
