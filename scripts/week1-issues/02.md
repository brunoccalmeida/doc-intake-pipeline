Title: feat(packs): receipt/invoice schema and extraction result with source citations
Labels: priority: P0

## Why
The schema is the contract every other piece checks against: the extractor validates against it, the golden set is converted to it and the eval compares fields from it. Citations are what make a field verifiable (`docs/ARCHITECTURE.md` D1).

## Scope
- `core`: generic result types: `Citation` (`page`, `quote`), `ExtractedField[T]` (`value: T | None`, `citation: Citation | None`, `reason` when empty), `ExtractionResult` (`status: ok | needs_review | failed`, fields, errors).
- `packs/receipt`: `Receipt` schema with the SROIE fields first (`company`, `address`, `date`, `total`) plus `currency` (optional). Money as `Decimal`, dates as `datetime.date`.
- Rules enforced by the schema, not by convention: a value requires a citation; an empty value requires a reason; `total` is non-negative.
- JSON Schema export of `Receipt` (what the provider receives).

## Acceptance criteria
- [ ] Unit tests, each seen failing first: valid result accepted; value without citation rejected; empty without reason rejected; negative total rejected; float total converted without binary rounding errors (`"10.10"` stays `Decimal("10.10")`).
- [ ] JSON Schema export covered by a snapshot test that fails when the schema changes by accident.

## Out of scope
Line items, tax breakdown (add when a client or the CORD set needs them).
