Title: test(evals): per-field accuracy, Markdown report and CI gate against regressions
Labels: priority: P0

## Why
This is the portfolio's centerpiece: proof that quality is measured and protected. See `docs/ARCHITECTURE.md` D4.

## Scope
- Scoring per field with documented rules (exact match after normalization, like SROIE's own protocol; `null` vs value counted as an error), plus per-status counts (`ok`, `needs_review`, `failed`).
- Markdown report: accuracy per field, failures listed by document and field, total cost and tokens.
- Decide and record how CI runs the eval. Recommendation (D4): score recorded provider responses keyed by a hash of prompt + document + model, with no key and no cost in CI; a missing recording fails CI and asks for a local re-record with a real key.
- Baseline committed; CI fails if any field's accuracy drops below the baseline (tolerance, if any, justified in the PR). Report posted as a job summary and uploaded as an artifact.

## Acceptance criteria
- [ ] Scoring unit-tested, each test seen failing first (normalization, `null` handling).
- [ ] RED proven: a deliberately worse prompt or a corrupted recording makes CI fail on the eval job, naming the field that dropped.
- [ ] Eval job in `ci-passed`'s `needs`.
- [ ] First real numbers in the README "At a Glance", linked to the CI run.

## Out of scope
LLM-as-judge, semantic similarity scoring.

Estimate: ~3 h
