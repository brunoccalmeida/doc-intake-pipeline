Title: feat(core): LLM extractor with swappable provider, validated output and bounded retry
Labels: priority: P0

## Why
This is the pipeline's core and where unreliable demos fail: invalid JSON, invented values, provider lock-in. See `docs/ARCHITECTURE.md` D2 and D3.

## Scope
- `LLMProvider` protocol: request (instructions, document text, JSON Schema) → response (raw text or structured output, token usage).
- Implementations for Claude and OpenAI in their own modules, selected by configuration; use each SDK's native structured output when available (check the official docs for the installed version). API keys only from validated settings.
- `extract(document, pack)`: call the provider, validate with the pack schema; on invalid output, retry with the validation error included, up to a configured limit (default 2); after that, return `failed` with the last error.
- Citation check: a citation whose quote is not found in the page text downgrades the field to `needs_review`.
- Fake provider for tests that returns scripted responses.

## Acceptance criteria
- [ ] Tests with the fake provider, each seen failing first: valid response → `ok`; malformed then valid → `ok` after one retry and the retry request contains the validation error; always malformed → `failed` after the limit, no partial result; fabricated quote → `needs_review`.
- [ ] `core` imports no provider SDK (enforced by a test or lint rule, proven with a probe).
- [ ] One manual run against each real provider on one document, with the command and cost recorded in the PR.

## Out of scope
Prompt tuning for accuracy (that is driven by the eval in #6).
